## 3. Problems we hit (and how we fixed them)

This is the most important section. Real problems = real learning.

### 🔴 Problem 1 — Typo in module path

**What happened:**
```bash
uvicorn src.gatway.app:app --reload   # missing 'e' in gateway
```

**Error:**
```
ModuleNotFoundError: No module named 'src.gatway'
```

**Fix:** Correct the spelling.
```bash
uvicorn src.gateway.app:app --reload   # ← gateway, not gatway
```

**Lesson:**
- Python errors point at the **last line first** — read bottom up.
- `ModuleNotFoundError` always means: "the path you typed doesn't match any folder/file."
- Tab-completion in the terminal saves typos. Type `src/ga<Tab>` — bash completes the rest if it's unambiguous.

---

### 🔴 Problem 2 — Tried to run before the code existed

**What happened:** Ran `uvicorn src.gateway.app:app` before `src/gateway/app.py` had been written. The folder was there, but the file wasn't.

**Error:** Same `ModuleNotFoundError` — Python found the folder but no `app.py` inside.

**Fix:** Wait for the code to be written before running it.

**Lesson:**
- Folders alone are not enough. Python needs the actual `.py` file.
- A folder becomes a Python package only with `__init__.py` AND it needs the modules inside it.
- `ls src/gateway/` is a quick sanity check — does the file exist?

---

### 🔴 Problem 3 — Typos in `curl` URL and content type

**What happened:**
```bash
curl -X POST http://localhost:8000/v1/cht ...   # missing 'a'
-H "Content-Type: application/joson"            # 'joson', not 'json'
```

**Error:**
```json
{"detail":"Not Found"}
```

**Fix:** Correct spellings.
```bash
curl -X POST http://localhost:8000/v1/chat ...
-H "Content-Type: application/json"
```

**Lesson:**
- `404 Not Found` = wrong URL. The server has no such route.
- Add `-i` to curl to see the **full HTTP response** including status code:
  ```bash
  curl -i -X POST ...
  ```
- Common HTTP statuses to know:
  | Code | Meaning |
  |------|---------|
  | 200 | OK — success |
  | 401 | Unauthorized — missing/wrong auth |
  | 404 | Not Found — wrong URL |
  | 422 | Unprocessable — bad JSON shape |
  | 500 | Server crashed (our bug) |
  | 503 | Service Unavailable — backend not configured |

## 4. What we learned (concepts)

### 🎓 Virtual environments (`venv`)

A **sandbox** for Python packages. Every project has its own `venv/` folder with its own libraries. **Always activate it** before working: `source venv/bin/activate`. To leave: `deactivate`.

**Why it matters:** Without venv, every `pip install` polluted the system Python. Five projects = five conflicts. With venv, each project is isolated.

---

### 🎓 `pydantic-settings`

A library that loads `.env` into a **typed Python object**.

```python
class Settings(BaseSettings):
    openai_api_key: str = ""
    gateway_port: int = 8000
```

Now `settings.gateway_port` is an `int`, not a string. If `.env` has `GATEWAY_PORT=abc`, the app fails at startup with a clear error — much better than crashing 30 minutes later.

**Why this, not `os.getenv()`?** Because `os.getenv()` returns strings only. You'd need to manually convert/validate every value. `pydantic-settings` does it automatically.

---

### 🎓 Abstract base classes (the `Backend` interface)

```python
class Backend(ABC):
    @abstractmethod
    async def chat(self, request): ...
    @abstractmethod
    def is_available(self) -> bool: ...
```

This is a **contract**: any class that inherits from `Backend` MUST have both methods. The gateway code doesn't care if the backend is OpenAI or Llama — it just calls `.chat()`.

**Why it matters:** When we add Llama in W7, we write one new class — zero changes anywhere else. This is called the **Strategy Pattern**.

---

### 🎓 FastAPI dependencies (auth)

```python
def require_api_key(x_api_key: str = Header(...)):
    if x_api_key != settings.gateway_api_key:
        raise HTTPException(401)

@app.post("/v1/chat", dependencies=[Depends(require_api_key)])
```

FastAPI runs `require_api_key` **before** the endpoint. If it raises, the endpoint never runs.

**Why this, not an `if` inside every endpoint?** Because we'd repeat the same code 50 times. With `Depends()`, write once, attach to every endpoint that needs it.

---

### 🎓 Middleware (logging)

```python
@app.middleware("http")
async def log_requests(request, call_next):
    response = await call_next(request)
    logger.info(...)
    return response
```

Middleware runs for **every** request — before and after. Perfect for cross-cutting concerns: logging, metrics, request IDs, CORS.

---

### 🎓 Auto-generated docs (`/docs`)

FastAPI reads our Pydantic models and generates a full **Swagger UI** for free. Visitors can test endpoints from the browser. No extra code.
